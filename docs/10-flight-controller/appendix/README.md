# 附錄:PX4 v1.17.0 介面全集

這裡是查詢用的,不是閱讀用的。[10 章正文](../)講的是為什麼飛控長這樣;這幾份是它實際暴露出來的每一個介面,從原始碼解析而來。

三份都由 [`tools/dump_px4_api.py`](../../../tools/dump_px4_api.py) 產生,釘在 PX4 `v1.17.0`。換版本重跑,不要手改。

| 檔 | 內容 | 規模 |
|---|---|---|
| [uorb-all-topics.md](uorb-all-topics.md) | 全部 uORB 訊息的欄位與常數,並區分對外契約與內部訊息 | 244 則(對外 34、內部 210) |
| [parameters-full.md](parameters-full.md) | 全部參數的型別、預設、範圍、單位、說明,依群組分類 | 2059 個、100 個群組 |
| [mavlink-command-support.md](mavlink-command-support.md) | PX4 能送出的 MAVLink 串流,以及它會處理的入站訊息 | 89 送 / 51 收 |

## 為什麼收在這裡而不是連到官方文件

官方的 [docs.px4.io](https://docs.px4.io/) 有參數與訊息參考,而且會持續更新。這裡多做一份,理由有三個。

**版本對得上。** 官方文件預設顯示 main 分支,而你手上跑的是某個 release。參數的預設值、範圍、甚至存不存在都會隨版本改,對照 main 去調 v1.17 的機器是常見的困惑來源。這裡每一份都釘死版本,寫在標題上。

**分得出哪些是承諾。** 244 則 uORB 訊息裡只有 34 則在 `msg/versioned/`,那 34 則才是刻意穩定下來的對外契約。官方參考把它們混在一起列,看不出這個差別——而這個差別決定你的伴隨電腦程式會不會在下次韌體升級時壞掉。

**可以離線、可以 grep、可以 diff。** 換版本重跑一次,把兩版產出丟進 `diff`,就得到「這個版本動了哪些參數與訊息」。這是升級韌體前最有用的一張表,而網頁版做不到。

## 這幾份的限制

- **解析的是原始碼,不是編譯出來的韌體。** 實際燒進板子的參數集取決於 build target 與啟用的模組,會比這裡少。
- **19 個參數在原始碼裡就沒有說明**,這裡照實留白,不代為推測。
- **入站訊息的清單來自 `mavlink_receiver.cpp` 的 `switch`**,少數透過其他路徑處理的訊息可能不在表上。
