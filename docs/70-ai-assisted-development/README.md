# 70 AI 協作開發

AI 工具的效益取決於回饋迴路的品質,而無人機領域預設的回饋迴路很差:啟動模擬要幾十秒、真機驗證要開車去空地、錯誤代價是摔一台機。所以問題不是「能不能用」,而是「哪些部分的驗證夠便宜」。

| 篇 | 主題 | 回答 |
|---|---|---|
| [01](01-boundaries.md) | 能力邊界 | 綠黃紅三區怎麼分、紅區的四個理由、這個領域特有的四種失敗模式、一個三問判斷準則 |
| [02](02-workflow.md) | 工作流與驗收 | 為什麼回饋迴路排第一、加一個任務動作的完整走查、專案該放什麼常駐脈絡、明確有效的五個用法、七個反模式 |

讀完應該能回答:

- 為什麼控制律與 failsafe 門檻不該交出去,理由不只是「危險」?
- 幻覺出來的 PX4 參數名怎麼在幾秒內識破?
- 情境測試通過之後,還有哪五件事必須人工檢查?
- 為什麼安全相關的斷言不該跟實作出自同一個來源?
