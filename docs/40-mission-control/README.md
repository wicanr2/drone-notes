# 40 任務控制

「Mission Controller」這個詞至少指三種東西,專案裡多數關於責任邊界的爭執,根源是雙方講的不是同一層。這一章把三層定下來,再分別展開機載與雲端的實作。

| 篇 | 主題 | 回答 |
|---|---|---|
| [01](01-three-layers.md) | 三層各在哪、責任怎麼切 | 為什麼是三層而非兩層、完整任務生命週期時序、唯一真相來源在哪、失效矩陣、三層的開源現成度 |
| [02](02-onboard-executor.md) | 機載任務執行器 | 動作抽象的五個方法各對應什麼失敗經驗、兩層狀態機、執行迴圈、Offboard 的借用模式、三種中斷的恢復策略、怎麼寫成可測試的 |
| [03](03-cloud-mission-service.md) | 雲端任務服務 | 跟一般後端的四個差異、定義/計畫/執行三分的資料模型、冪等與版本、事件的亂序重複遲到、派工選機、離線設計、合規稽核 |

讀完應該能回答:

- 飛行期間任務進度的權威在哪一層,為什麼不是雲端?
- 機載執行器重啟後,為什麼不能直接從上次的動作續行?
- Offboard 為什麼要「先送再切、切回再停」?
- 派工 API 的冪等鍵應該是什麼,少了它會發生什麼?

對應的可跑實作在 [`reference-impl/`](../../reference-impl/)。
