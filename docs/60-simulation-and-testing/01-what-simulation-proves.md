# 模擬能證明什麼、不能證明什麼

「在模擬裡跑過了」這句話的資訊量,完全取決於你跑的是哪一層的模擬、驗的是哪一類問題。有些結論可以直接外推到真機,有些則完全不能——而把後者當成前者,是這個領域最貴的錯誤之一。

這一章先把模擬拆開看它到底在近似什麼,再給一張「哪些結論可以外推」的對照表。

---

## 1. 模擬在做什麼:用模型取代世界

模擬把[控制迴路](../00-system-overview/01-the-control-loop.md)裡的「物理世界」那一格換成程式:

```
真實:  感測器 ← 物理世界 ← 致動器
模擬:  感測器模型 ← 物理引擎 ← 致動器模型
```

**其餘的部分都是真的。** SITL 跑的是真的飛控韌體、真的 EKF、真的控制律、真的狀態機。這一點很重要,因為它決定了外推的邊界:凡是不依賴物理保真度的東西,模擬的結論就成立。

那麼模型跟現實差多少?按項目拆開,差距非常不平均:

| 被模擬的東西 | 保真度 | 為什麼 |
|---|---|---|
| 剛體動力學(質量、慣量、力矩) | **高** | 牛頓力學,方程式明確 |
| 螺旋槳推力與扭矩 | 中 | 常用簡化模型,忽略入流、地面效應、槳間干擾 |
| 空氣動力(固定翼、風、紊流) | 中至低 | 完整計算太貴,模擬用查表或經驗式 |
| IMU 雜訊與偏差 | 中 | 可建模,但每顆晶片的參數不同 |
| GNSS 行為 | 中至低 | 多路徑、遮蔽、電離層很難模擬 |
| 磁場環境 | **低** | 機體自身電流造成的干擾幾乎無法預測 |
| 相機影像 | 看工具而定 | 這正是 Isaac Sim 這類工具存在的理由 |
| 電池在低溫高負載下的電壓 | 低 | 化學行為複雜 |
| 機械振動與結構共振 | **極低** | 跟實際組裝方式強相關 |
| 電磁干擾、鏈路品質 | **極低** | 跟現場環境強相關 |

看這張表可以直接得出一條原則:**振動、磁干擾、鏈路品質這三類問題,模擬永遠驗不出來,只能靠真機。** 反過來,狀態機與協定這類完全不碰物理的東西,模擬的結論可以百分之百外推。

---

## 2. 哪些結論可以外推

| 你在模擬裡驗證的 | 能不能外推 | 說明 |
|---|---|---|
| 模式切換的條件與順序 | ✅ 可以 | 純邏輯,跑的是真韌體 |
| 任務協定的交握 | ✅ 可以 | 純協定 |
| failsafe 觸發後的行為 | ✅ 可以 | 邏輯正確,但觸發門檻的真實值要另外驗 |
| 任務狀態機的中斷與恢復 | ✅ 可以 | 純邏輯 |
| 座標系轉換是否正確 | ✅ 可以 | 數學 |
| 控制律的**定性**行為(會不會發散、方向對不對) | ✅ 大致可以 | 剛體動力學保真度高 |
| 控制增益的**具體數值** | ⚠️ 部分 | 要看模型參數跟真機有多接近 |
| 視覺演算法的可行性 | ⚠️ 部分 | 看模擬影像的擬真度 |
| 端到端延遲 | ❌ 不行 | 模擬的排程與真實硬體不同 |
| CPU 佔用與即時性 | ❌ 不行 | 用 SIH 或 HITL 驗 |
| 振動對感測器的影響 | ❌ 不行 | 只能真機 |
| 磁干擾造成的航向漂移 | ❌ 不行 | 只能真機 |
| 鏈路在實際距離下的表現 | ❌ 不行 | 只能現場 |

**這張表就是「模擬跑過了」這句話的定價表。** 報告裡寫「已在模擬驗證」時,應該同時說明驗的是哪一類,否則接收方會自動假設是最強的那一類。

---

## 3. 模擬的真正價值不是「像」,是「可重複」

追求擬真度容易讓人忘記模擬最大的優勢:**同樣的輸入會得到同樣的輸出**。

真機測試的根本問題是不可重複:今天有風、明天沒風,這次電池滿電、那次八成。所以真機測試無法回答「我這個修改到底有沒有讓情況變好」——你永遠不知道差異是來自修改還是來自環境。

模擬把這個變數消掉了。於是可以做到:

- **回歸測試**:每次改動跑同一組情境,行為變了就知道
- **二分搜尋**:哪一次提交開始壞掉,一個一個跑就找得出來
- **故障注入**:讓 GNSS 在第 47 秒消失,每次都在第 47 秒
- **極端情境**:電量只剩 5% 的行為,不必真的把電池放到 5%
- **大量重複**:同一個情境跑一百次看有沒有偶發問題

這些能力對「保證系統行為正確」的貢獻,遠大於畫面像不像。所以建驗證系統時的優先順序應該是:**先讓它可重複、可自動化,再談保真度。**

## 4. 縮小模擬與真機的落差

需要提高保真度時,可用的手段由便宜到貴:

**參數辨識。** 拿真機的飛行紀錄反推模型參數:實際的推力係數、慣量、阻力。這是投報率最高的一步——用一次真飛的資料就能讓模擬的動力學貼近很多。

**感測器參數對齊。** 把真機 IMU 的雜訊密度、偏差穩定度量出來,填進模擬的感測器模型。

**情境隨機化。** 每次執行隨機改變風速、感測器偏差、質量、延遲。這不是為了更像真實,而是**逼演算法不能依賴某個特定條件**。從模擬訓練的視覺或強化學習模型要能用在真機,這一步是必要的。

**硬體迴路。** 把真的飛控板接進來(HITL),或在真板子上跑內建模擬(SIH)。這補上時序與 CPU 負載,這兩項純軟體模擬給不了。

**繫留測試。** 把機器固定在測試台上通電運轉,量振動、電流、溫度。這是唯一能驗證振動與熱的方式,而且安全。

## 5. 一個常見的推理錯誤

「模擬跑了一百次都沒問題,所以這個修改是安全的。」

這句話有兩個漏洞:

**第一,一百次跑的是同一個情境。** 如果模擬是確定性的,跑一百次跟跑一次的資訊量相同。要有價值,必須每次的初始條件與擾動不同,而且要說明隨機了什麼。

**第二,沒出問題不代表驗證通過。** 系統可能因為某個保護機制救了場而「看起來正常」,實際上你要驗的邏輯根本沒被執行到。所以測試不能只斷言「有沒有崩」,要斷言**預期的事件確實發生了**——例如「failsafe 在第 47 秒觸發,且行為是返航」。

沒有正向斷言的測試,通過與不通過的資訊量是一樣的。

---

## 6. 這一章的結論

1. 模擬只換掉物理世界那一格,其餘跑的是真韌體,所以不依賴物理保真度的結論可以外推。
2. 剛體動力學保真度高,振動、磁干擾、鏈路品質幾乎完全模擬不出來。
3. 邏輯、協定、狀態機、座標轉換的驗證可以外推;延遲、CPU、振動、磁干擾不行。
4. 模擬最大的價值是可重複,而不是像;建系統時先追求可自動化再追求保真度。
5. 提高保真度的順序:參數辨識 → 感測器對齊 → 情境隨機化 → 硬體迴路 → 繫留測試。
6. 「跑一百次沒問題」若情境相同就等於跑一次;測試要有正向斷言,不能只斷言沒崩。
