# 從飛行包絡到航跡規劃

航跡規劃不是在地圖上畫線。**線畫出來之後,飛機能不能照著飛、要飛多久、電夠不夠,全部由機體參數決定。** 一條在地圖上看起來很合理的航線,可能因為轉彎半徑不夠、航點太密、或風向不對,實際飛起來比預估慢一倍。

這一章把[上一篇的機體參數](01-platform-parameters.md)變成可以算的約束,再說明這些約束該落在飛控參數還是任務服務邏輯裡。

---

## 1. 風:最容易被低估的一項

規劃時最常見的錯誤是用空速估任務時間。飛機在空氣裡飛,地面上的距離要用**地速**算,而地速 = 空速 ± 風速。

### 往返航線的時間倍率

一條來回距離各 `d` 的航線,空速 `v`,沿航線風速 `w`:

```
往返時間 T = d/(v−w) + d/(v+w) = 2dv / (v² − w²)

相對無風的倍率 = v² / (v² − w²)
```

這條式子的行為很不直覺——不是「逆風慢的跟順風快的抵銷」,而是**一定變慢,而且風速接近空速時急遽發散**:

| 空速 16 m/s 下的風速 | 時間倍率 | 白話 |
|---|---|---|
| 4 m/s | 1.07 | 多 7%,幾乎沒感覺 |
| 8 m/s | 1.33 | 多 33%,任務時間要重估 |
| 10 m/s | 1.64 | 多 64% |
| 12 m/s | **2.29** | 時間變兩倍以上 |
| 14 m/s | **4.27** | 逆風段幾乎在原地 |
| 16 m/s | ∞ | 逆風走不動 |

對照[上一篇](01-platform-parameters.md)的規格:WingtraOne 巡航 16 m/s、抗風上限 12 m/s。**在 12 m/s 的風下它「飛得起來」,但往返時間變兩倍以上,能覆蓋的面積只剩不到一半。** 這就是「抗風上限不等於可作業風速」的定量版本。

側風的影響則是要偏一個角度去抵銷,有效前進速度變成 `√(v²−w²)`:側風等於空速的一半時,有效速度掉到 86.6%;等於 0.75 倍時掉到 66%。

### 規劃上的兩條實務原則

**先逆風去、順風回。** 回程時電量最低,而順風回耗能最少。反過來規劃的話,最糟的情況是「去程順風飛得很爽,回程逆風飛不回來」。

**任務時間要用當天的風重算,不能用晴天的數字。** 這代表任務服務必須接氣象資料,而且是**飛行高度的風**,不是地面測站的風——兩者可以差不少。

## 2. 固定翼:最小轉彎半徑決定航線幾何

固定翼靠側傾產生向心力,轉彎半徑是:

```
R = v² / (g · tan φ)      φ = 側傾角
```

代入實際機型:

| 機型 | 巡航速度 | 側傾 30° | 側傾 45° |
|---|---|---|---|
| WingtraOne GEN II | 16 m/s | 45 m | 26 m |
| Trinity F90+ | 17 m/s | 51 m | 29 m |
| 假想 25 m/s 機型 | 25 m/s | 110 m | 64 m |

注意 `R ∝ v²`:速度加倍,轉彎半徑變四倍。這是為什麼快的固定翼在小場地幾乎沒辦法作業。

### 對測繪航線的實際影響

測繪航線是一組平行線。**掉頭需要的橫向空間是 2R**,而航線間距通常遠小於這個值(高解析度測繪常在數十公尺)。所以掉頭不可能用一個簡單的半圓完成,要飛出作業區外做額外機動:

```
航線間距 40 m,R = 45 m  →  2R = 90 m > 40 m
→ 必須飛出區域外,用更長的路徑繞回來
→ 每次掉頭的額外距離大約是 πR,約 140 m,以 16 m/s 計約 9 秒
→ 一片區域若有 30 條航線,光掉頭就多花約 4.5 分鐘
```

規劃時要處理的三件事:**作業區外要留緩衝空間**(至少 R,通常留 1.5R);**掉頭路徑要算進總時間**;**航線方向最好順著長邊**,以減少掉頭次數。順著長邊還有一個額外好處——如果同時順著風向,長航段的地速偏差最小。

多旋翼沒有這個限制(轉彎半徑可以是 0),這是它在小區域、不規則邊界的作業上勝過固定翼的地方。代價是覆蓋效率低一截。

## 3. 多旋翼:加速度上限決定航點能多密

多旋翼靠傾斜產生水平力,所以水平加速度受最大傾角限制:

```
a_max = g · tan θ_max
```

| 最大傾角 | 水平加速度 |
|---|---|
| 25° | 4.6 m/s² |
| 30° | 5.7 m/s² |
| 35° | 6.9 m/s² |

由此得到一條規劃時非常好用的式子。一個長度 `L` 的航段,如果要在中點前加速、中點後減速並停在終點,能達到的最高速度是:

```
v_peak = √(a · L)
```

| 航段長度 | 30° 傾角下能達到的最高速度 |
|---|---|
| 20 m | 10.6 m/s |
| 50 m | 16.8 m/s |
| 100 m | 23.8 m/s |
| 200 m | 33.6 m/s(通常先撞到速度上限) |

**這解釋了一個常見的困惑:航點加密之後,任務反而變慢。** 因為每個航點都要求「到達」,飛機在每段都要加速再減速,平均速度遠低於巡航速度。20 公尺一個航點的航線,實際平均速度可能只有巡航速度的三分之一。

處理方式有兩種:**放寬航點的到達判定**(讓飛機不必真的停在點上就算通過,PX4 用 `NAV_ACC_RAD` 這類參數控制),或**在規劃時就不要放那麼多航點**——直線段上的中間點對飛行沒有貢獻,只有拖慢速度。

### 垂直方向

爬升與下降是分開的兩個限制,而且不對稱:爬升受推力餘裕限制,下降受**渦環狀態**限制——多旋翼垂直下降太快時會掉進自己製造的下洗氣流,升力驟降而且難以恢復。所以下降速率的上限通常比爬升低,而且**帶著水平速度斜著下降比垂直下降安全**。

規劃時的具體影響:高度變化要算時間(從 100 m 降到 20 m,以 2 m/s 計要 40 秒),而且盡量安排成斜降而不是原地垂降。

## 4. 能量預算與動態返航門檻

### 一趟任務要多少能量

```
E_total = E_起飛爬升 + E_去程 + E_任務 + E_回程 + E_下降降落 + E_保留
```

其中去程與回程的時間要用**含風的地速**算,而 `E_保留` 不是一個固定百分比——它應該是「從目前位置回到降落點所需的能量」加上餘裕。

### 固定百分比的返航門檻是錯的

「電量剩 20% 就返航」這種設定,在飛機離家 200 公尺時太保守,在離家 5 公里且逆風時遠遠不夠。**正確的門檻是動態的**:

```
返航所需時間 ≈ 距離 / (巡航空速 − 回程逆風分量) + 高度差 / 下降率 + 降落時間
返航所需能量 ≈ 返航所需時間 × 回程平均功率 × 安全係數
觸發門檻    = 返航所需能量 + 餘裕
```

值得注意的是**飛控本身已經在做這件事**。PX4 的 RTL 有兩個參數專門處理這個估算:

| 參數 | 意義 | 預設 |
|---|---|---|
| `RTL_TIME_FACTOR` | 返航時間估計的安全係數 | 1.1(可設 1.0~2.0) |
| `RTL_TIME_MARGIN` | 在係數之後再加上的固定餘裕(秒) | 100 |

也就是 `含餘裕的時間 = RTL_TIME_FACTOR × 估計時間 + RTL_TIME_MARGIN`。

這件事對分層有直接意涵:**飛控的動態返航門檻是最後防線,任務服務應該有一條更早、更保守的線。** 呼應[任務控制那章](../40-mission-control/02-onboard-executor.md)的原則——讓保護機制成為「不應該發生的事」。如果你的任務每次都是被飛控的 RTL 中止的,那是任務規劃的能量預算算錯了,不是 failsafe 好用。

## 5. 這些約束落在哪一層

同一組物理限制,會以兩種形式存在:飛控裡的參數,以及任務服務裡的規劃邏輯。分工要清楚。

### 飛控參數(限制「飛機願意做什麼」)

以下參數名取自 PX4 main 分支的參數定義檔:

| 參數 | 管什麼 |
|---|---|
| `MPC_XY_VEL_MAX` | 多旋翼最大水平速度 |
| `MPC_TILTMAX_AIR` | 最大傾角 → 決定水平加速度上限 |
| `MPC_ACC_HOR` | 水平加速度 |
| `MPC_Z_VEL_MAX_UP` / `MPC_Z_VEL_MAX_DN` | 上升 / 下降速率上限 |
| `NAV_ACC_RAD` | 航點的到達判定半徑 |
| `NAV_MC_ALT_RAD` / `NAV_FW_ALT_RAD` | 高度方向的到達判定 |
| `NAV_LOITER_RAD` | 盤旋半徑 |
| `FW_R_LIM` | 固定翼最大側傾 → 決定最小轉彎半徑 |
| `FW_AIRSPD_MIN` / `FW_AIRSPD_TRIM` | 失速餘裕與巡航空速 |
| `RTL_RETURN_ALT` / `RTL_DESCEND_ALT` | 返航高度剖面 |
| `RTL_TIME_FACTOR` / `RTL_TIME_MARGIN` | 返航時間估計的安全係數與餘裕 |
| `BAT_LOW_THR` / `BAT_CRIT_THR` / `BAT_EMERGEN_THR` | 三段電量門檻 |

這些是**硬邊界**:飛控不會超過它們,任務規劃也不能假設它能超過。

### 任務服務邏輯(決定「要不要飛、怎麼飛」)

| 邏輯 | 用到的參數 |
|---|---|
| 可飛性檢查 | 能量預算、酬載重量、抗風上限 vs 預報風速 |
| 選機 | 酬載匹配、覆蓋半徑、續航折損後的可用值 |
| 航線生成 | 最小轉彎半徑、航段長度下限、緩衝區 |
| 時間估算 | 含風地速、掉頭額外距離、加減速損耗 |
| 中止判斷 | 動態返航門檻(比飛控更早的那條線) |
| 時窗選擇 | 風速預報、日照、空域授權 |

**兩層的關係是:飛控保證不做危險的事,任務服務保證不安排做不到的事。** 前者是安全,後者是效率;混在一起會兩邊都做不好。

## 6. 可飛性檢查清單

把上面的東西收斂成一組任務服務該跑的檢查。每一項不過都要能說出原因:

- [ ] 起飛重量(空機 + 電池 + 酬載)未超過 MTOW
- [ ] 酬載介面與型號匹配這台機
- [ ] 折算後的可用續航 ≥ 任務所需時間 × 安全係數
- [ ] 任務所需時間已用當天預報風速重算
- [ ] 最遠航點的返航能量 ≤ 觸發門檻前的剩餘能量
- [ ] 預報風速(含陣風)未超過機體抗風上限的安全比例
- [ ] 航線的最小轉彎半徑符合機型(固定翼)
- [ ] 作業區外有足夠的掉頭緩衝空間(固定翼)
- [ ] 航段長度不會讓飛機無法達到規劃速度
- [ ] 高度變化的時間已算入
- [ ] 電池健康度與循環數在可用範圍
- [ ] 空域授權涵蓋這條航線與時窗

這份清單應該是程式,不是紙本流程。**任何一項不過,派工就該被系統擋下並說明原因**——「為什麼這台沒被派到」是營運端最常問的問題。

## 7. 這一章的結論

1. 往返時間倍率是 `v²/(v²−w²)`:風速到空速的四分之三時,時間就變兩倍以上。抗風上限不等於可作業風速。
2. 規劃要先逆風去、順風回,因為回程電量最低;任務時間要用飛行高度的預報風重算。
3. 固定翼的最小轉彎半徑 `R = v²/(g·tanφ)`,`R ∝ v²`;掉頭需要 2R 的橫向空間,作業區外要留緩衝,掉頭時間要算進總時程。
4. 多旋翼的水平加速度是 `g·tanθ`;一個航段能達到的最高速度是 `√(a·L)`,所以航點加密會讓任務變慢。
5. 返航門檻要動態計算,而 PX4 已經用 `RTL_TIME_FACTOR` 與 `RTL_TIME_MARGIN` 做這件事;任務服務要有更早的那一條線。
6. 物理限制以兩種形式存在:飛控參數是硬邊界,任務服務邏輯決定要不要飛;飛控保證不做危險的事,任務服務保證不安排做不到的事。
