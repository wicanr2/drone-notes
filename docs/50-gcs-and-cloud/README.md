# 50 地面站與雲端

地面站是這套系統裡唯一直接影響人類決策的元件;機隊平台則在規模化之後,資料量會變成主要成本。這一章談這兩件事的工程取捨。

| 篇 | 主題 | 回答 |
|---|---|---|
| [01](01-gcs-architecture.md) | 地面站的架構與自研界線 | 四層架構、載具模型層為什麼最常被忽略、什麼該自研什麼不該、攸關安全的介面原則、遙測更新率該設多少 |
| [02](02-fleet-and-data.md) | 機隊營運與資料治理 | 一趟任務產生多少資料(算給你看)、資料分層與保留、機隊狀態模型、法規接點、SaaS 與私有化、系統整合 |

讀完應該能回答:

- 為什麼不該自研參數校正功能?
- 位置資料停止更新時,介面應該顯示什麼?
- 十台機每天各飛五趟,一年產生多少資料,這對架構有什麼影響?
- 為什麼電池要當成獨立實體管理而不是機器的屬性?
